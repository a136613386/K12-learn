## 2. 背景与目标

### 2.1 业务背景

当前 K12-learn 已完成 Web MVP：学生输入一道高中生物错题，系统通过 BERT/FastText 识别知识点，并推荐同类强化题。该版本验证了“错题归类 + 强化练习”的最小闭环。

下一阶段目标不是做一个简单网页套壳，而是面向真实学生学习场景，形成移动端学习闭环：

1. 学生登录并形成个人学习身份。
2. 录入错题并完成知识点识别、错因分析、同类练习。
3. 系统沉淀学生薄弱知识点、错因、练习记录和复习节奏。
4. 通过意图识别、查询改写和大模型输出，为学生、教师、教研和运营提供不同场景能力。

### 2.2 产品定位

MVP Android v1 定位为：

> 面向高中生物学习场景的安卓错题归因与个性化强化学习 App。

第一版聚焦学生端学习闭环，不追求完整大而全平台。教师、教研和客资分析在 v1 提供基础数据能力与后台接口预留，完整运营后台放在后续版本。

### 2.3 业务目标

| 目标 | 说明 | MVP 指标 |
| --- | --- | --- |
| 建立学生学习身份 | 支持学生登录、学习记录归属、历史错题沉淀 | 学生可登录并查看自己的历史错题 |
| 提升错题处理效率 | 输入错题后返回知识点、错因、强化题 | 单次归因与推荐可在 App 内完成 |
| 建立记忆管理基础 | 记录知识点掌握度、错因和复习时间 | 每个学生生成薄弱知识点列表 |
| 支持 App 内测 | 安卓真机可安装、可连接后端服务 | 可生成 debug APK 并完成核心流程 |
| 支撑后续商业化 | 为教师看板、教研出题、客资分析积累数据 | 关键行为事件可记录和统计 |

## 3. 范围定义

### 3.1 MVP Android v1 做什么

P0 范围：

- 安卓 App 基础形态，优先采用 Vue 移动端适配 + Capacitor 打包。
- 学生登录与当前用户信息。
- 错题输入、知识点分类、BERT/FastText 兜底状态展示。
- 错因分析结果展示。
- 同类强化题推荐，答案默认收起。
- 练习记录与历史错题记录。
- 薄弱知识点列表与基础掌握度。
- 服务端继续承载模型推理和大模型调用，App 不在本地运行模型。

P1 范围：

- 拍照上传入口，OCR 可先占位或接入后端预留接口。
- 每日强化任务。
- 教师/教研基础数据接口。
- 用户客资基础事件埋点。

P2 范围：

- 完整教研出题后台。
- 完整教师班级看板。
- 完整运营 CRM 和销售线索管理。
- 离线题库、本地模型推理。
- 非安卓 App 端（本期仅支持 Android App）。

### 3.2 本期不做什么

- 不重写为 Flutter 或 React Native。
- 不把 BERT、FastText、大模型部署到手机端。
- 不做完整多学科、多教材版本。
- 不做开放式 AI 聊天产品。
- 不做未经审核的自动出题直接投放给学生。
- 不做面向销售的学生隐私明细导出。

## 5. 核心业务流程

### 5.1 学生学习主流程

```text
学生打开安卓 App
  -> 登录/获取当前学生身份
  -> 输入或上传错题
  -> 系统识别用户意图
  -> 查询改写为结构化学习任务
  -> 知识点分类模型识别知识点
  -> BERT 不可用或低置信度时 FastText 兜底
  -> 大模型生成错因分析和讲解
  -> 推荐同类强化题
  -> 学生查看答案/完成练习
  -> 系统记录错题、错因、练习结果、知识点掌握度
  -> 生成薄弱知识点和后续学习路径
```

### 5.2 AI 编排流程

```text
原始输入
  -> 意图识别
      - 错题归因
      - 知识点问答
      - 同类题生成
      - 学习路径查询
      - 教研出题
  -> 查询改写
      - 学科
      - 年级
      - 题干
      - 选项
      - 学生答案
      - 正确答案
      - 目标任务
  -> 模型分类
      - BERT 优先
      - FastText 兜底
      - 关键词最终降级
  -> 大模型输出
      - 错因
      - 解题步骤
      - 知识点解释
      - 学习建议
      - 强化题推荐说明
  -> 记忆管理
      - 错题记录
      - 错因记录
      - 练习记录
      - 掌握度更新
```

## 6. 用户场景与用户故事

### 6.1 学生错题归因

作为学生，我希望把做错的题输入 App，系统告诉我这道题属于哪个知识点、为什么错、应该再练哪些题，以便我针对薄弱点复习。

验收标准：

- 学生必须先登录或以有效学生身份进入。
- 输入错题文本后，可以看到知识点、置信度、模型状态、错因和同类强化题。
- 当 BERT 低置信度时，页面显示 FastText 兜底结果。
- 强化题答案默认收起。
- 本次错题和推荐结果写入学生历史记录。

### 6.2 学生记忆管理

作为学生，我希望 App 记住我哪些知识点经常错、哪些错因反复出现，以便每天按薄弱点复习。

验收标准：

- App 展示“我的薄弱知识点”。
- 每个知识点展示错题次数、练习次数、最近练习时间、掌握度。
- 完成练习后掌握度发生更新。

### 6.3 教研出题

作为教研人员，我希望根据知识点、难度、题型和错因生成题目草稿，并由人工审核后入库，以便持续扩充高质量题库。

验收标准：

- MVP v1 至少预留题目生成任务结构。
- 自动生成题目不得直接进入学生正式题库。
- 题目入库前必须有人工审核状态。

### 6.4 个性化学习路径

作为学生，我希望 App 根据我的错题记录给出今天应该练什么，以便减少无目标刷题。

验收标准：

- App 根据薄弱知识点生成每日强化列表。
- 优先推荐高频错误、高重要度、低掌握度知识点。
- 每日任务完成状态可记录。

### 6.5 用户客资分析

作为机构运营人员，我希望看到学生活跃、学习完成、薄弱知识点和潜在转化线索，以便做教学服务和运营跟进。

验收标准：

- 系统记录登录、错题提交、练习完成、查看答案、连续学习等事件。
- MVP 只输出聚合数据和学习行为数据。
- 不向销售人员暴露未成年人敏感个人信息明细。

## 7. 功能需求

### 7.1 安卓 App 基础形态（P0）

需求描述：

将现有 Vue 前端改造成移动端优先页面，并通过 Capacitor 打包安卓 App。

功能要求：

- 保持当前后端 API 调用方式。
- App 使用底部导航组织页面。
- 适配安卓常见屏幕宽度，避免横向滚动。
- 支持后端 API 地址按环境配置。
- 首期模型推理仍由后端完成。

建议页面：

| 页面 | 内容 |
| --- | --- |
| 错题页 | 错题输入、提交、归类结果、同类强化题 |
| 练习页 | 今日强化、推荐练习、答案收起 |
| 记录页 | 历史错题、历史练习 |
| 我的页 | 用户信息、薄弱知识点、服务状态、退出登录 |

验收标准：

- 安卓模拟器或真机可运行。
- 核心流程可在 390px 宽度下正常使用。
- 不出现文字遮挡、按钮溢出和横向滚动。

### 7.2 学生登录（P0）

需求描述：

提供学生身份体系，为错题记录、记忆管理和学习路径提供基础。

功能要求：

- 支持账号/手机号登录。
- 支持获取当前用户信息。
- 登录状态在 App 本地保存。
- 后端接口可识别 `user_id`。

接口建议：

```http
POST /api/v1/auth/login
POST /api/v1/auth/logout
GET /api/v1/auth/me
```

验收标准：

- 未登录用户访问学习记录时提示登录。
- 登录后提交错题，记录归属当前用户。
- 退出登录后清除本地登录状态。

### 7.3 错题归因（P0）

需求描述：

在当前“知识点分类 + 同类强化题”基础上，增加错因分析。

错因类型建议：

| 错因 | 说明 |
| --- | --- |
| 概念不清 | 对知识点定义、规律、术语理解错误 |
| 审题错误 | 忽略条件、限定词、问法 |
| 推理错误 | 遗传图解、比例推导、过程判断错误 |
| 选项干扰 | 被相近概念或错误表述干扰 |
| 知识迁移不足 | 无法将知识点应用到新情境 |
| 实验分析不足 | 实验目的、变量、结论判断错误 |

验收标准：

- 错题结果页展示知识点、错因、解题建议和强化题。
- 错因结果写入错题记录。
- 大模型输出失败时，仍返回知识点分类和强化题。

### 7.4 意图识别（P0）

需求描述：

识别用户输入意图，避免所有输入都按错题归因处理。

意图类型：

| 意图 | 说明 |
| --- | --- |
| wrong_question_analysis | 错题归因 |
| knowledge_qa | 知识点问答 |
| similar_question_request | 同类题请求 |
| learning_path_request | 学习路径查询 |
| teaching_research_question | 教研出题 |

验收标准：

- 输入题干类文本时，默认进入错题归因。
- 输入“帮我出 5 道伴性遗传题”时，识别为教研/同类题任务。
- 意图识别低置信度时，提示用户补充信息或默认进入错题归因。

### 7.5 查询改写（P0）

需求描述：

将学生自然语言输入改写为结构化任务，提升分类和大模型输出稳定性。

结构化字段：

```json
{
  "subject": "高中生物",
  "grade": "高中",
  "task_type": "wrong_question_analysis",
  "stem": "",
  "options": "",
  "student_answer": "",
  "correct_answer": "",
  "target": "错题归因与强化练习"
}
```

验收标准：

- 原始输入和改写结果均可记录。
- 改写失败不阻断基础分类。
- 改写结果用于大模型提示词和后续数据分析。

### 7.6 大模型输出（P0）

需求描述：

大模型负责解释、错因、学习建议，不直接替代知识点分类模型。

输出内容：

- 错因判断。
- 关键知识点解释。
- 解题步骤。
- 学习建议。
- 推荐练习理由。

验收标准：

- 大模型输出必须基于题干、分类结果和题库上下文。
- 输出必须可降级，大模型不可用时不影响 BERT/FastText 分类。
- 输出不能编造不存在的题目 ID 或题库内容。

### 7.7 记忆管理（P0）

需求描述：

记录学生错题、练习、错因和掌握度，形成个性化学习路径基础。

核心对象：

| 对象 | 说明 |
| --- | --- |
| 错题记录 | 学生每次提交的题目、分类、错因、推荐结果 |
| 练习记录 | 学生完成强化题的答题情况 |
| 知识点掌握度 | 每个学生在每个知识点上的掌握分 |
| 复习计划 | 系统生成的每日强化任务 |

验收标准：

- 学生可查看自己的历史错题。
- 学生可查看薄弱知识点。
- 完成强化题后更新练习记录。

### 7.8 个性化学习路径（P1）

需求描述：

基于错题和掌握度生成每日强化建议。

初始规则：

- 错题次数越多，优先级越高。
- 知识点重要程度越高，优先级越高。
- 最近未复习时间越长，优先级越高。
- 连续答对后降低推荐频率。

验收标准：

- 每日生成 5-10 道强化题。
- 学生可看到任务完成状态。
- 无足够题库时展示不足提示。

### 7.9 教研出题（P1/P2）

需求描述：

面向教研人员提供题目生成、审核、入库流程。

MVP v1 只做数据结构和接口预留；完整后台在后续版本实现。

题目状态：

| 状态 | 说明 |
| --- | --- |
| draft | AI 生成草稿 |
| reviewing | 待人工审核 |
| approved | 审核通过 |
| rejected | 审核驳回 |
| published | 可推荐给学生 |

验收标准：

- AI 生成题目不得绕过人工审核直接发布。
- 题目必须包含知识点、难度、答案、解析和来源。

### 7.10 用户客资分析（P1/P2）

需求描述：

记录学习行为事件，为机构后续运营和转化分析提供基础。

埋点事件：

| 事件 | 触发时机 |
| --- | --- |
| app_open | 打开 App |
| login_success | 登录成功 |
| wrong_question_submit | 提交错题 |
| classification_success | 分类成功 |
| answer_expand | 展开答案 |
| practice_complete | 完成练习 |
| daily_task_complete | 完成每日任务 |
| weak_point_view | 查看薄弱知识点 |

验收标准：

- 事件包含 `user_id`、时间、页面、业务对象 ID。
- 客资分析优先使用聚合数据。
- 未成年人数据必须进行权限隔离和最小化展示。

## 10. 非功能需求

### 10.1 性能

- App 首屏冷启动目标小于 3 秒。
- 错题归因接口目标小于 3 秒，大模型解释可异步或分阶段返回。
- BERT 不可用或低置信度时，FastText 兜底必须可用。
- Redis 不可用时不阻塞主流程。

### 10.2 可用性

- 后端模型不可用时，App 必须展示明确降级状态。
- 网络失败时保留用户输入，不清空页面。
- 大模型失败时仍展示知识点分类和强化题。
- 题库不足时展示明确提示。

### 10.3 安全与合规

- 密码不得明文存储。
- 登录态需有过期机制。
- 学生数据按用户隔离。
- 未成年人数据遵循最小化采集、最小化展示原则。
- 运营和销售侧默认只能查看聚合数据，不查看学生敏感明细。
- 上线前需准备隐私政策、用户协议、数据删除机制。

### 10.4 兼容性

- Android 8.0 及以上优先支持。
- 首期只要求 Android App。
- Web H5 保持可开发调试。
- API 地址支持开发、测试、生产环境配置。

## 11. 技术实现建议

### 11.1 推荐架构

```text
Android App
  -> Capacitor WebView
  -> Vue 移动端页面
  -> Flask API
  -> AI 编排层
      - 意图识别
      - 查询改写
      - BERT/FastText 分类
      - 大模型解释
  -> MySQL / Redis / 模型文件 / 题库
```

### 11.2 推荐开发路线

第一阶段不直接打包 App，而是先完成移动端 H5 形态：

1. Vue 页面移动端改造。
2. 底部导航和页面拆分。
3. 学生登录。
4. 学习记录与掌握度。
5. 再接 Capacitor 打包 Android。

### 11.3 API 地址策略

开发环境：

```text
安卓模拟器访问电脑后端: http://10.0.2.2:8000/api/v1
真机局域网访问电脑后端: http://{电脑局域网 IP}:8000/api/v1
生产环境: https://api.yourdomain.com/api/v1
```

前端应通过环境变量配置：

```text
VITE_API_BASE_URL=...
```

## 12. 里程碑与排期

### Phase 1：移动端 H5 改造

目标：现有 Web MVP 变成手机可用形态。

交付物：

- 移动端布局。
- 底部导航。
- 错题页、练习页、记录页、我的页。
- 当前接口调用保持可用。

验收：

- 手机浏览器 390x844 尺寸可完整使用。
- 无横向滚动和关键文字遮挡。

### Phase 2：登录与记忆管理

目标：形成学生个人学习数据。

交付物：

- 登录接口和登录页。
- 错题记录绑定用户。
- 练习记录。
- 知识点掌握度。

验收：

- 学生登录后可查看自己的历史错题和薄弱知识点。

### Phase 3：AI 编排升级

目标：补齐意图识别、查询改写和大模型解释。

交付物：

- 意图识别接口。
- 查询改写结构。
- 大模型解释输出。
- 错因分析。

验收：

- 错题结果页展示错因、解释和学习建议。
- 大模型失败时基础分类流程不受影响。

### Phase 4：Capacitor 安卓打包

目标：生成可安装安卓 App。

交付物：

- Capacitor Android 工程。
- debug APK。
- 环境 API 配置。

验收：

- 安卓模拟器或真机安装后可登录、提交错题、查看推荐题。

### Phase 5：内测上线准备

目标：小范围机构或学生内测。

交付物：

- 后端部署。
- HTTPS API。
- 日志监控。
- 隐私政策和用户协议。
- 基础数据看板。

验收：

- 可支持小范围真实用户试用。
- 核心链路有日志、异常和数据统计。

## 13. 验收标准总表

| 模块 | P0 验收标准 |
| --- | --- |
| 安卓 App | 真机或模拟器可安装运行 |

| 安全 | 用户数据隔离，密码不明文存储 |

## 14. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 直接打包现有 PC 页面体验差 | App 可用但不好用 | 先做移动端 H5 改造，再打包 |
| 大模型输出不稳定 | 错因和解释质量不稳定 | 分类模型做确定性结果，大模型只做解释，可降级 |
| 题库不足 | 个性化路径推荐质量低 | 优先补高频知识点题库，题目必须人工审核 |
| BERT 推理慢 | App 等待时间长 | FastText 兜底、缓存、异步解释 |
| 学生数据合规风险 | 影响上线和商业化 | 最小化采集、权限隔离、隐私政策、审计日志 |
| 安卓网络调试复杂 | 新手易卡住 | 明确模拟器使用 `10.0.2.2`，真机使用局域网 IP |
| 训练输出覆盖线上模型 | 模型文件被占用或线上异常 | 训练目录和线上模型目录隔离，发布时再切换 |
