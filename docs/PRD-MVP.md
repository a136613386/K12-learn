## 2. 背景与目标

### 2.1 背景

K12-learn 项目聚焦 K12 教育场景，首期范围限定为高中生物必修2《遗传与进化》。当前计划以每人 500 道题的数据规模进行知识点分类标注，并基于 BERT 模型训练一个题目知识点分类能力。

项目技术方向已确定为 Flask + Python + MySQL + Redis + BERT + Git。参考项目为 `D:\xuweiqun\py_project\work_heima\大模型三阶段\01_投满分`，其中 `04-bert` 可作为模型训练和推理的初始参考。

### 2.2 MVP 目标

MVP 只解决一个核心问题：输入一道高中生物必修2题目文本，系统返回该题最可能对应的知识点。

可量化目标：

| 指标 | MVP 目标 |
| --- | --- |
| 数据闭环 | 支持导入、训练、预测、查看结果 |
| 题目范围 | 高中生物必修2《遗传与进化》 |
| 分类粒度 | 先支持一级/二级知识点，后续再细化 |
| 训练数据 | 至少完成 500 道题的标注样本 |
| 模型能力 | 在验证集输出 accuracy、macro F1 |
| 接口能力 | 提供一个可调用的预测 API |
| 响应时间 | 单条预测 CPU 环境下尽量控制在 2 秒内 |

## 3. MVP 范围

### 3.1 本期做什么

P0 范围：

- 建立高中生物必修2知识点标签体系。
- 整理题目训练数据，形成可训练的文本分类数据集。
- 基于 BERT 训练知识点分类模型。
- 提供 Flask API，支持输入题目文本并返回知识点预测结果。
- 提供 Vue 前端基础页面，支持题目输入、预测结果展示、耗时展示和历史记录查看。
- 使用 MySQL 存储题目、知识点、预测记录。
- 使用 Redis 缓存重复题目的预测结果。
- 提供基础 README，说明如何准备数据、训练模型、启动服务、调用接口。

### 3.2 本期不做什么

MVP 暂不包含：

- 学生端完整学习系统。
- 教师端后台管理页面。
- 用户登录、权限、班级管理。
- 个性化推荐和学习路径。
- 错题本、掌握度画像。
- 多学科、多教材版本支持。
- 大模型生成题目或解析。
- 模型压缩、蒸馏、量化。
- 复杂前端后台，如权限管理、题库批量运营、训练任务管理。

## 4. 用户场景

### 4.1 题库标注人员

作为题库标注人员，我希望按照统一知识点体系标注题目，以便形成可用于模型训练的数据集。

验收标准：

- 能看到知识点标签清单。
- 每道题可以对应一个主要知识点。
- 标注结果可以导出为训练文件。

### 4.2 模型开发人员

作为模型开发人员，我希望使用已标注题目训练 BERT 分类模型，以便得到可用于预测的模型文件。

验收标准：

- 可以运行训练脚本。
- 训练完成后生成模型文件。
- 控制台输出 accuracy、macro F1 等指标。

### 4.3 API 调用方

作为 API 调用方，我希望传入一道题目文本后获得知识点预测结果，以便后续接入题库系统或学习系统。

验收标准：

- API 接收 JSON 格式请求。
- API 返回知识点 ID、知识点名称、置信度、耗时。
- 输入为空或格式错误时返回明确错误。

### 4.4 教研/演示用户

作为教研或演示用户，我希望通过一个简单页面输入题目并查看预测结果，以便快速验证模型是否能识别高中生物知识模块。

验收标准：

- 页面可以输入或粘贴题目文本。
- 页面可以展示预测知识模块、置信度、重要程度、难度、核心要求。
- 页面可以展示本次预测耗时、是否命中缓存。
- 页面可以查看最近预测记录。

### 5.2 题目数据整理（P0）

需求描述：

将题库数据整理为模型可训练格式。

训练文件格式：

```text
题目文本\t知识点标签ID
```

题目文本拼接规则：

```text
题干 [SEP] 选项
```

如果存在解析，MVP 阶段默认不拼接解析，避免模型学习到答案泄露特征。后续可实验对比。

验收标准：

- 至少包含 `train.txt`、`dev.txt`、`test.txt`。
- 每行包含题目文本和标签 ID，中间使用 tab 分隔。
- 标签 ID 必须存在于知识点标签清单。
- 数据集切分建议为 8:1:1。

### 5.3 BERT 模型训练（P0）

需求描述：

基于中文 BERT 模型训练高中生物题目知识点分类模型。

输入：

- `train.txt`
- `dev.txt`
- `test.txt`
- `class.txt`

输出：

- 模型权重文件。
- 训练日志。
- 测试集评估报告。

验收标准：

- 可通过命令启动训练。
- 训练完成后保存最佳模型。
- 每轮训练后在验证集评估。
- 最终在测试集输出 accuracy、macro F1、每类 precision/recall。

### 5.4 题目知识点预测 API（P0）

需求描述：

提供 Flask API，接收题目文本，返回预测知识点。

接口：

```http
POST /api/v1/predict/knowledge-point
```

请求示例：

```json
{
  "text": "豌豆高茎与矮茎杂交，F1 全为高茎，F2 中高茎与矮茎的比例约为 3:1。该现象体现了什么遗传规律？"
}
```

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "knowledge_point_id": 0,
    "knowledge_point_name": "孟德尔遗传定律",
    "confidence": 0.92,
    "elapsed_ms": 185.3,
    "cache_hit": false,
    "importance": 5,
    "difficulty": 4,
    "core_requirement": "会判断显隐性、分离比、基因型和表现型"
  }
}
```

异常响应示例：

```json
{
  "code": 400,
  "message": "text is required",
  "data": null
}
```

验收标准：

- 支持 JSON 请求。
- 空文本返回 400。
- 模型未加载成功时返回 500，并记录日志。
- 正常请求返回知识点 ID、名称、置信度、耗时、是否命中缓存、重要程度、难度、核心要求。

### 5.5 前端展示 API（P0）

需求描述：

后台需提供若干轻量 API，供 Vue 前端展示知识点、预测记录、统计信息和服务状态。所有接口统一返回 JSON，格式为：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

#### 5.5.1 获取知识点列表

```http
GET /api/v1/knowledge-points
```

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "id": 0,
      "name": "孟德尔遗传定律",
      "importance": 5,
      "difficulty": 4,
      "core_requirement": "会判断显隐性、分离比、基因型和表现型",
      "sort_order": 1
    }
  ]
}
```

#### 5.5.2 获取最近预测记录

```http
GET /api/v1/predictions/recent?limit=10
```

响应字段：

- `id`：预测记录 ID。
- `input_text`：输入文本，前端可截断展示。
- `knowledge_point_name`：预测知识模块。
- `confidence`：置信度。
- `elapsed_ms`：预测耗时。
- `cache_hit`：是否命中缓存。
- `created_at`：预测时间。

#### 5.5.3 获取首页统计

```http
GET /api/v1/stats/overview
```

响应字段：

- `knowledge_point_count`：知识点数量。
- `prediction_count`：累计预测次数。
- `avg_elapsed_ms`：平均预测耗时。
- `cache_hit_count`：缓存命中次数。
- `latest_prediction_at`：最近一次预测时间。

#### 5.5.4 获取服务健康状态

```http
GET /api/v1/health
```

响应字段：

- `status`：服务状态，取值 `ok` 或 `error`。
- `model_loaded`：模型是否加载成功。
- `mysql_connected`：MySQL 是否连通。
- `redis_connected`：Redis 是否连通。

验收标准：

- 前端可通过 API 渲染知识点列表、最近预测记录、统计卡片和服务状态。
- API 参数错误返回明确错误信息。
- 所有接口返回结构统一，便于前端处理。
- 后台允许前端本地开发域名跨域访问。

### 5.7 Redis 预测缓存（P1）

需求描述：

对重复输入文本进行缓存，减少重复模型推理。

MVP 默认 Redis 配置：

```env
# ===== Redis 配置（VM）=====
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=
```

实现要求：

- 服务默认读取 `.env` 或环境变量中的 Redis 配置。
- 本地开发和验收阶段使用上述 VM Redis 配置。
- Redis 不可用时只跳过缓存，不阻断预测 API。

缓存 key：

```text
predict:knowledge_point:{text_hash}
```

缓存 value：

```json
{
  "knowledge_point_id": 0,
  "knowledge_point_name": "孟德尔遗传定律",
  "confidence": 0.92,
  "importance": 5,
  "difficulty": 4,
  "core_requirement": "会判断显隐性、分离比、基因型和表现型"
}
```

验收标准：

- 相同文本第二次请求优先命中 Redis。
- 缓存默认有效期 24 小时。
- Redis 不可用时不影响模型预测主流程。

## 6. 非功能需求

### 6.1 性能

- 单条预测接口在 CPU 环境下目标响应时间小于 2 秒。
- 重复文本命中 Redis 后目标响应时间小于 200 ms。
- MVP 不要求高并发，支持本地或单机部署即可。

### 6.2 稳定性

- 模型加载失败时服务启动应给出明确错误。
- API 参数错误不能导致服务崩溃。
- Redis/MySQL 异常需记录日志。

### 6.3 可维护性

- Flask API、模型推理、数据库访问、配置文件分层管理。
- Vue 前端与 Flask 后端分离，前端通过统一 API 调用后端。
- 路径配置不写死在训练和推理代码中。
- 训练数据、模型文件不提交到 Git，使用 `.gitignore` 排除。

### 6.4 安全

- MVP 暂不做用户认证。
- API 只用于本地或内网测试。
- 数据库与 Redis 地址在 PRD 中明确，代码实现时通过 `.env` 或环境变量读取，不直接写死在业务代码中。

## 8. 里程碑与排期

以最快可落地为目标，建议按 6 个工作日完成 MVP。

| 阶段 | 时间 | 交付内容 |
| --- | --- | --- |
| Day 1 | 项目骨架 | Flask 工程结构、配置、README 初稿、知识点标签 |
| Day 2 | 数据闭环 | 样例数据、数据校验脚本、训练集切分 |
| Day 3 | 模型训练 | BERT 训练脚本、评估报告、模型保存 |
| Day 4 | 后台 API | 推理模块、预测接口、展示 API、MySQL 预测日志 |
| Day 5 | 前端页面 | Vue 预测工作台、结果卡片、最近记录、统计展示 |
| Day 6 | 联调验收 | Redis 缓存、异常处理、前后端联调、文档完善 |

## 9. 验收标准

MVP 验收以“能跑通”为第一标准。

必须满足：

- 能启动 Flask 服务。
- 能启动 Vue 前端页面。
- 能调用预测 API。
- 能在页面输入题目并展示预测结果。
- 能返回并展示知识点 ID、名称、置信度、耗时。
- 能保存预测记录到 MySQL。
- 有可训练的数据格式和训练脚本。
- 有 README 说明完整运行流程。

建议满足：

- Redis 缓存重复预测结果。
- 页面展示缓存命中状态、重要程度、难度、核心要求。
- 页面展示最近预测记录和基础统计。
- 输出测试集分类报告。
- 至少准备 500 条人工标注样本。

暂不要求：

- 前端登录、权限、复杂后台管理。
- 用户系统。
- 线上部署。
- 大规模并发。
- 高精度模型指标。

## 10. 风险与依赖

| 风险 | 影响 | 应对方式 |
| --- | --- | --- |
| 标注数据不足 | 模型效果不稳定 | 先跑通流程，再逐步扩充数据 |
| 知识点粒度过细 | 类别混淆严重 | MVP 先用 15 个左右核心标签 |
| 参考代码耦合较重 | 迁移成本上升 | 只复用思路，代码重新分层 |
| CPU 推理较慢 | API 响应慢 | 使用 Redis 缓存，后续再做模型压缩 |
| 数据标签不一致 | 训练失败或结果错误 | 增加数据校验脚本 |

## 11. 后续版本规划

MVP 之后再考虑：

- 题库管理后台。
- 学生作答记录。
- 错题知识点归因。
- 学生知识点掌握度。
- 练习推荐。
- 模型效果对比：BERT、FastText、传统 ML。
- 模型压缩：蒸馏、剪枝、量化。
- 支持更多教材章节和学科。
