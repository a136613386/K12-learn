## 2. 背景与目标

### 2.1 背景

K12-learn 项目聚焦 K12 教育场景，首期范围限定为高中生物必修2《遗传与进化》。项目技术方向为 Flask + Python + MySQL + Redis + BERT + Vue。

MVP 不再只是"能预测知识点"，而是面向学生真实学习场景：**学生遇到一道错题，系统不仅告诉 TA 这道题考什么知识点，还能给 TA 同一知识点的强化练习题，帮助 TA 通过针对性练习巩固薄弱环节。**

### 2.2 MVP 目标

MVP 解决的核心问题：**输入一道错题文本，系统返回该题对应的知识点分类 + 同一知识点下最多 5 道强化题（含答案）。**

可量化目标：

| 指标 | MVP 目标 |
| --- | --- |
| 错题归类 | 输入错题文本，返回知识点名称、置信度、难度、重要程度、核心要求 |
| 同类题推荐 | 返回同知识点下最多 5 道强化题，每题含题干和答案 |
| 题目范围 | 高中生物必修2《遗传与进化》，15 个知识模块 |
| 题库规模 | 至少覆盖 15 个知识模块，每个模块至少 5 道题 |
| 响应时间 | 单次请求（分类 + 推荐）CPU 环境下目标 < 2 秒 |
| 记录留存 | 每次错题归类与推荐结果写入数据库，为后续错题本和掌握度分析打基础 |

## 3. MVP 范围

### 3.1 本期做什么（P0）

- 建立高中生物必修2 知识点标签体系（15 个知识模块）。
- 建立题库，每个知识模块至少 5 道题（含题干、答案、知识点归属）。
- 基于 BERT 训练知识点分类模型。
- 提供 Flask API，输入错题文本，返回知识点分类 + 同知识点强化题推荐。
- 提供 Vue 前端页面，展示：错题输入区、知识点分类结果、置信度、核心要求、推荐题目列表及答案。
- 使用 MySQL 存储知识点、题库、错题归类与推荐记录。
- 使用 Redis 缓存重复题目的分类与推荐结果。
- 提供 README 说明完整运行流程。

### 3.2 本期不做什么

MVP 暂不包含：

- 学生端完整学习系统。
- 用户登录、权限、班级管理。
- 个性化推荐（基于学生历史掌握度的差异化推荐）。
- 错题本产品（累计展示、筛选、回顾）。
- 掌握度画像与学习路径规划。
- 多学科、多教材版本支持。
- 大模型生成题目或解析。
- 模型压缩、蒸馏、量化。
- 教师端后台管理页面。
- 题库批量运营后台。

## 4. 用户场景

### 4.1 学生（核心用户）

作为学生，我希望把做错的题目输入系统，系统告诉我这道题考的是哪个知识点，并给我几道同一知识点的练习题（附答案），以便我针对薄弱知识点进行强化训练。

验收标准：

- 可以在输入框中粘贴或输入一道错题文本。
- 提交后能看到该错题对应的知识点名称、置信度、难度、重要程度、核心学习要求。
- 能看到最多 5 道同知识点强化题，每道题展示题干和答案。
- 同知识点题目不足 5 道时，展示已有题目并提示数量不足。
- 无推荐题时，展示空状态提示，不报错。

### 4.2 教研/演示用户

作为教研或演示用户，我希望通过页面快速验证：输入一道题 → 系统正确归类 → 推荐的题目确实属于同一知识模块。

验收标准：

- 页面完整展示错题归类 → 推荐结果的全流程。
- 能查看最近错题归类与推荐的历史记录。

### 4.3 模型开发人员

作为模型开发人员，我希望使用已标注题目训练 BERT 分类模型，并确保推荐接口能基于分类结果正确查询题库。

验收标准：

- 可运行训练脚本并保存模型。
- 训练完成后输出 accuracy、macro F1 等指标。
- 推荐接口能根据分类结果从题库中正确筛选题目。

## 5. 核心业务流程

```
学生遇到一道错题
      ↓
将错题文本输入 K12-learn
      ↓
系统使用知识点分类模型判断错题所属知识模块
      ↓
系统展示该知识点的名称、置信度、难度、重要程度和核心学习要求
      ↓
系统从题库中查询同知识点题目
      ↓
返回最多 5 道同分类强化题，并附带答案
      ↓
学生通过同类题进行针对性复习
      ↓
系统记录错题归类和推荐结果，为后续错题本、掌握度分析和个性化推荐打基础
```

## 6. 功能需求

### 6.1 知识点标签体系（P0）

需求描述：

建立高中生物必修2 知识点标签体系，共 15 个知识模块，作为分类标签和推荐依据。

| 标签 ID | 排序 | 知识模块 | 重要程度 | 难度 | 核心要求 |
| --- | --- | --- | --- | --- | --- |
| 0 | 1 | 孟德尔遗传定律 | ★★★★★ | ★★★★☆ | 会判断显隐性、分离比、基因型和表现型 |
| 1 | 2 | 减数分裂与受精作用 | ★★★★★ | ★★★★★ | 会分析染色体、DNA、染色单体数量变化 |
| 2 | 3 | 伴性遗传 | ★★★★★ | ★★★★☆ | 会分析红绿色盲、抗维生素D佝偻病等遗传图解 |
| 3 | 4 | DNA是主要遗传物质 | ★★★★★ | ★★★☆☆ | 掌握肺炎链球菌转化实验、噬菌体侵染细菌实验 |
| 4 | 5 | DNA结构与复制 | ★★★★★ | ★★★★☆ | 掌握双螺旋、碱基互补配对、半保留复制 |
| 5 | 6 | 基因指导蛋白质合成 | ★★★★★ | ★★★★★ | 掌握转录、翻译、密码子、氨基酸关系 |
| 6 | 7 | 基因表达与性状关系 | ★★★★☆ | ★★★★☆ | 理解基因、蛋白质、性状之间的关系 |
| 7 | 8 | 基因突变和基因重组 | ★★★★☆ | ★★★★☆ | 区分突变、重组及其在变异中的意义 |
| 8 | 9 | 染色体变异 | ★★★★☆ | ★★★★☆ | 掌握结构变异、数目变异、染色体组 |
| 9 | 10 | 人类遗传病 | ★★★★☆ | ★★★☆☆ | 会区分单基因、多基因、染色体异常遗传病 |
| 10 | 11 | 基因在染色体上 | ★★★★☆ | ★★★☆☆ | 理解萨顿假说、摩尔根果蝇实验 |
| 11 | 12 | 现代生物进化理论 | ★★★★☆ | ★★★★☆ | 掌握自然选择、基因频率、物种形成 |
| 12 | 13 | 生物共同祖先证据 | ★★★☆☆ | ★★☆☆☆ | 掌握化石、比较解剖学、胚胎学等证据 |
| 13 | 14 | 协同进化与生物多样性 | ★★★☆☆ | ★★★☆☆ | 理解共同进化和生物多样性的形成 |
| 14 | 15 | 探究实践与模型实验 | ★★★☆☆ | ★★★☆☆ | 会解释模拟实验、观察实验和调查实验目的 |

`class.txt` 内容：

```text
孟德尔遗传定律
减数分裂与受精作用
伴性遗传
DNA是主要遗传物质
DNA结构与复制
基因指导蛋白质合成
基因表达与性状关系
基因突变和基因重组
染色体变异
人类遗传病
基因在染色体上
现代生物进化理论
生物共同祖先证据
协同进化与生物多样性
探究实践与模型实验
```

验收标准：

- 项目中存在 `class.txt` 且数据库 `knowledge_points` 表数据一致。
- 标签 ID 与训练数据、题库中的 `knowledge_point_id` 一一对应。
- 数据库知识点表保存排序、重要程度、难度、核心要求。

### 6.2 题库管理（P0）

需求描述：

建立题库，存储每道题的题干、选项、答案及所属知识点，作为推荐的题目来源。每个知识模块至少 5 道题。

数据库表 `question_bank`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 题目 ID（自增） |
| stem | text | 题干 |
| options | text | 选项（JSON 数组或文本） |
| answer | varchar | 答案 |
| knowledge_point_id | int | 所属知识点 ID，关联 knowledge_points.id |
| difficulty | tinyint | 难度 1-5 |
| source | varchar | 题目来源 |

验收标准：

- 每个知识模块至少有 5 道题入库。
- 题目可通过 `knowledge_point_id` 查询。
- 题库支持后续扩展（增加解析、题型等字段）。

### 6.3 BERT 模型训练（P0）

需求描述：

基于中文 BERT 模型训练高中生物题目知识点分类模型。

输入：

- `train.txt` / `dev.txt` / `test.txt`
- `class.txt`

输出：

- 模型权重文件
- 训练日志
- 测试集评估报告（accuracy、macro F1、每类 precision/recall）

验收标准：

- 可通过命令启动训练。
- 训练完成后保存最佳模型。
- 最终在测试集输出评估指标。

### 6.4 错题归类与推荐 API（P0）

需求描述：

提供 Flask API，输入错题文本，返回知识点分类 + 同知识点强化题推荐。这是 MVP 核心接口，一次请求完成"归类 + 推荐"。

接口：

```http
POST /api/v1/predict/knowledge-point
```

请求示例：

```json
{
  "text": "豌豆高茎与矮茎杂交，F1 全为高茎，F2 中高茎与矮茎的比例约为 3:1。该现象体现了什么遗传规律？"
}
```

响应示例（正常，有推荐题）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "knowledge_point_id": 0,
    "knowledge_point_name": "孟德尔遗传定律",
    "confidence": 0.92,
    "importance": 5,
    "difficulty": 4,
    "core_requirement": "会判断显隐性、分离比、基因型和表现型",
    "elapsed_ms": 185.3,
    "cache_hit": false,
    "recommendations": [
      {
        "id": 101,
        "stem": "在豌豆杂交实验中，F2 代出现 3:1 性状分离比的条件是什么？",
        "options": "[\"A. 完全显性\", \"B. 不完全显性\", \"C. 共显性\", \"D. 以上都是\"]",
        "answer": "A"
      },
      {
        "id": 102,
        "stem": "某植物红花（AA）与白花（aa）杂交，F1 自交后 F2 的表现型比例为？",
        "options": "[\"A. 全红\", \"B. 红:白=1:1\", \"C. 红:白=3:1\", \"D. 红:白=9:7\"]",
        "answer": "C"
      }
    ],
    "recommendation_count": 5,
    "recommendation_sufficient": true
  }
}
```

响应示例（推荐不足 5 道）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "knowledge_point_id": 14,

    "importance": 3,

    "core_requirement": "会解释模拟实验、观察实验和调查实验目的",

    "recommendations": [
      {
        "id": 301,
        "stem": "以下哪个实验属于模拟实验？",
        "options": "[\"A. 观察洋葱表皮细胞\", \"B. 用计算机模拟种群增长\", \"C. 调查红绿色盲发病率\", \"D. 提取DNA\"]",
        "answer": "B"
```

异常响应：

```json
{
  "code": 400,
  "message": "text is required",
  "data": null
}
```

```json
{
  "code": 500,
  "message": "model not loaded",
  "data": null
}
```

响应字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| knowledge_point_id | int | 知识点 ID |
| knowledge_point_name | string | 知识点名称 |
| confidence | float | 分类置信度 |
| importance | int | 重要程度 1-5 |
| difficulty | int | 难度 1-5 |
| core_requirement | string | 核心学习要求 |
| elapsed_ms | float | 请求耗时（毫秒） |
| cache_hit | bool | 是否命中缓存 |
| recommendations | array | 推荐题目列表（0-5 道） |
| recommendations[].id | bigint | 题目 ID |
| recommendations[].stem | string | 题干 |
| recommendations[].options | string | 选项（JSON 格式） |
| recommendations[].answer | string | 答案 |
| recommendation_count | int | 实际推荐数量 |
| recommendation_sufficient | bool | 推荐是否满足 5 道 |

验收标准：

- 支持 JSON 请求。
- 空文本返回 400。
- 模型未加载时返回 500 并记录日志。
- 正常请求返回知识点分类 + 推荐题目列表。
- 同知识点题目 >= 5 道时返回 5 道，`recommendation_sufficient` 为 true。
- 同知识点题目 < 5 道时返回实际数量，`recommendation_sufficient` 为 false。
- 同知识点无题目时返回空数组，`recommendation_count` 为 0，不报错。
- 返回的知识点信息包含难度、重要程度、核心要求。
- 推荐逻辑可配置返回数量上限（默认 5）。


验收标准：

- 允许前端本地开发域名跨域访问。

### 6.7 Redis 预测缓存（P1）

需求描述：

对相同文本的错题归类与推荐结果进行缓存，避免重复推理和数据库查询。

配置方式：

- Redis 连接参数（Host、Port、Password、DB）一律通过 `.env` 文件或环境变量配置。
- PRD 不指定具体 Redis 地址，以项目 `.env` 文件为准。
- 代码中不得硬编码 Redis 连接信息。

缓存 key：

```text
predict:mistake:v1:{text_hash}
```

缓存 value（JSON）：

```json
{
```

## 7. 非功能需求

### 7.1 性能

- 单次请求（分类 + 推荐）CPU 环境下目标 < 2 秒。
- 命中 Redis 缓存后目标 < 200 ms。
- MVP 不要求高并发，支持本地或单机部署。

### 7.2 稳定性

- 模型加载失败时服务启动应给出明确错误。
- API 参数错误不能导致服务崩溃。
- 题库为空或某知识点无题目时，推荐返回空数组，不报错。
- Redis / MySQL 异常需记录日志。

### 7.3 可维护性

- Flask API、模型推理、数据库访问、配置文件分层管理。
- Vue 前端与 Flask 后端分离。
- 训练数据、模型文件不提交到 Git。
- 推荐题目数量上限可配置（默认 5）。

### 7.4 安全

- MVP 暂不做用户认证。
- API 只用于本地或内网测试。
- 数据库与 Redis 配置通过 `.env` 读取，不硬编码。

## 10. 验收标准

### 必须满足（P0）

- 能启动 Flask 服务。
- 能启动 Vue 前端页面。
- 输入一道错题文本，能返回知识点分类 + 推荐题目。
- 页面能展示：知识点名称、置信度、难度、重要程度、核心要求。
- 页面能展示最多 5 道强化题，每道题含题干和答案。
- 同知识点题目不足 5 道时，展示已有题目并提示数量不足。
- 同知识点无题目时，展示空状态，不报错。
- 每次请求将归类与推荐结果写入 MySQL。
- 有 README 说明完整运行流程。

### 建议满足（P1）

- Redis 缓存重复题目的分类与推荐结果。
- 页面展示最近错题归类与推荐记录。
- 页面展示服务状态和基础统计。
- 输出测试集分类报告（accuracy、macro F1）。
- 每个知识模块至少 5 道题库题目。

### 暂不要求

- 用户登录、权限、复杂后台管理。
- 错题本产品（累计展示、筛选、回顾）。
- 个性化推荐（基于历史掌握度）。
- 线上部署。
- 大规模并发。
- 高精度模型指标。

## 11. 风险与依赖

| 风险 | 影响 | 应对方式 |
| --- | --- | --- |
| 题库数据不足（每模块 < 5 道） | 推荐结果少，体验差 | 优先确保核心模块有充足题目，不足的展示提示信息 |
| 知识点分类准确率低 | 推荐题目不相关 | MVP 先用关键词匹配兜底，后续用 BERT 微调提升 |
| CPU 推理较慢 | API 响应慢 | Redis 缓存 + 后续模型压缩 |
| 训练数据不足 | 模型效果不稳定 | 先用关键词规则跑通流程，逐步扩充标注数据 |
| 数据标签不一致 | 训练失败 | 增加数据校验脚本 |

## 12. 后续版本规划

MVP 之后再考虑：

- 错题本产品：按知识点/时间查看历史错题，筛选、回顾。
- 学生知识点掌握度画像：基于错题归类记录计算薄弱知识点。
- 个性化推荐：根据学生掌握度差异化推荐题目难度和数量。
- 题库管理后台：录入、编辑、批量导入题目。
- 用户系统：学生/教师登录、班级管理。
- 模型效果对比：BERT、FastText、传统 ML。
- 模型压缩：蒸馏、剪枝、量化。
- 多学科、多教材版本支持。
